# ver0.9 歌词辅助校对首版落地报告

> 状态：首版代码完成，针对性测试与浏览器交互检查通过；未运行 GPU 合成验证。
> 设计基线：[design.md](design.md)。实施前设计提交：`6a0b652`。
> 本报告只覆盖本轮歌词校对和罗马音显示改动，不覆盖工作区已有的模型等其他改动。

## 1. 用户入口与操作

SYN 编辑器工具栏新增书本图标“歌词辅助校对”。SYN 尚无 Segment 时入口禁用。

1. 首次进入，选择工程已有参考，或一次粘贴整首/一段歌词。
2. 选择 Segment，临时浮层显示当前文字、读音及匹配候选。点击候选后填入草稿。
3. 原文和读音可以手改。改原文后必须重新生成或明确确认保留读音，避免原文正确而读音仍旧。
4. “确认并继续”保存校对草稿，尚不覆盖 Segment；“跳过”可在后续待处理导航中返回。
5. 从列表图标打开修改预览，将当前有效、已确认的草稿一次应用。可撤销和重做。
6. 改了读音的句子显示控制待更新，可显式重新对齐 Kana 或按修正 Segment 更新 H。

只有复杂操作才展开参考全文与相邻片段弹窗。没有新增常驻侧栏或歌词轨；空间不足时使用临时弹窗。当前句周围试听、相邻片段联合试听均不改变 Segment 边界。

## 2. 已落地的匹配与时间关系

- 按参考文字范围匹配，不按歌词行分配，支持跨行与半句。
- 使用原文、假名读音的宽松子串匹配，容忍一定插入、删除和替换。
- 利用前后识别文字、已经确认的相邻范围，以及相同参考下其他 SYN 的时间定位给候选排序。
- 实际时间由实例 timelineStart 与 Segment frame/frameRate 相加；没有实例时只使用相对时间。
- 时间线实例的完整时长需与 Guide 时长相符，否则不套用简单加法。
- 同一源 SYN 的不同实例分别保存确认位置；新复制的实例不会自动继承旧位置。
- 保留重复歌词候选，允许同一参考范围被重复引用，也允许暂不确定位置而先确认文字。
- 参考版本、Guide 与 Segment 内容/边界变更会使旧草稿需要复核；无效草稿不混入有效子集的批量应用。

当前使用有余量的局部排序加全文兜底，而非严格禁止范围外候选。位置余量为至少 16 个原文索引单位，随当前句长度增加；跨 SYN 时间候选容忍 1.5 秒偏差；最多显示 8 个排序候选。这些是首版启发式参数，不是经过真实歌曲集校准的准确率承诺。

## 3. 数据与读音

工程对象树新增可选 lyricProofreading 数据，保存参考歌词及版本、各 SYN 会话、草稿和实例定位。数据随现有工程保存/加载流程持久化。旧工程没有该字段时仍正常打开。

文字校对写回源 SYN，引用它的时间线实例共同看到更新。预览显示实例共享关系。应用保持 Segment ID、起止 frame、MIDI-P、Guide 和历史 Take 不变。

新增 CPU 读音接口 `POST /api/lyrics/reading`，使用现有 Whisper Python 环境中的 Sudachi 和 jaconv，不加载 Whisper 或 GPU 模型。返回参考文本的 UTF-16 范围与假名读音。转换不可用时仍可保存参考并手工填写读音。

字符引用与发音分配可以不同：读音匹配落在词语内部时保留整词参考范围，草稿读音可以只取实际唱出的部分。相邻段通过切换当前段分别校对，没有新增同时编辑多段时间边界的工具。

## 4. Kana/H 更新

原文改写但读音不变时不要求重算 H，并保留已有 Romaji。读音变化则保留待更新状态；保存文字并不表示合成控制已经更新。

更新按钮复用现有 Segment -> Kana/H 入口及 GPU 容量、版本校验和手工覆盖确认。进入该流程时关闭校对浮层，避免遮挡原有确认窗口。只在覆盖范围与修订来源符合条件的 Segment -> H 操作后解除对应提示；清空 H 不能冒充完成更新。

没有自动执行整首对齐，也没有新增批量 GPU 队列。

## 5. 显示罗马音

设置新增“歌词显示 -> 显示罗马音”，默认关闭。

- 影响 SYN Segment/Kana、其检查栏和编辑框、校对浮层与预览，以及旧文本轨/文本编辑器。
- 仅控制显示；隐藏不删除已有 Romaji，Kana 与 Romaji 的原有数据转换仍保留。
- 使用 `GET/PUT /api/ui-preferences` 读取与保存，持久化到后端 `server/data/ui-preferences.json`。
- 该开关不写入浏览器 localStorage，启动时以后端值为准，跨工程共用。
- 保存期间禁用开关；写入失败保持上次成功值并在设置页显示错误，提供重新读取入口。
- “恢复默认”也将关闭状态写到后端。

现有主题、透明度等其他偏好仍使用原来的存储方式，本次没有整体迁移设置系统。

## 6. 实现文件

- `client/src/components/synthesis/LyricProofreader.vue`：校对入口、浮层/弹窗、草稿、预览和局部对齐衔接。
- `client/src/object-workbench/lyricProofreading.ts`：范围匹配、实例时间、草稿有效性与应用事务。
- `client/src/components/synthesis/SynthesisUnitEditor.vue`：Segment 状态、Guide 区间试听、选择定位与罗马音显示。
- `client/src/object-workbench/types.ts`：工程可选校对数据。
- `server/scripts/lyric_reading.py`、`server/src/services/lyric-reading.service.ts`：CPU 读音转换。
- `server/src/services/ui-preferences.service.ts`、`server/src/index.ts`：显示偏好持久化与接口。
- `client/src/stores/uiSettings.ts`、`client/src/App.vue`、设置页和文本显示组件：加载/保存开关并响应显示。

## 7. 验证

- 前端 TypeScript/Vue 检查通过，后端 TypeScript 构建通过。
- 校对 13 个针对性测试通过：跨行、漏字、UTF-16 范围、词内读音、重复使用、邻段排序、跨 SYN 实际时间、实例隔离、失效草稿、子集应用、撤销和控制状态等。
- UI 设置 6 个测试通过，包含后端读取、保存请求、默认关闭、本地存储排除以及失败保留原值。
- 后端偏好文件测试通过：默认值、写入、重建 repository 后恢复、拒绝非布尔值。
- 使用独立无头 Chrome 的临时工程检查了真实页面交互：导入参考、真实 CPU 读音接口、候选填入、确认应用、撤销重做、保存并刷新后恢复草稿。
- 检查了 1440x1000 与 700x720 视口的截图和浮层边界，没有新增时间线常驻空间。
- 通过设置页切换罗马音，验证后端值与刷新后的显示恢复；测试结束恢复原来的偏好值。

浏览器验证使用内存中的临时工程并拦截项目保存，不修改用户已有工程文件。未使用 Tabbit。

## 8. 限制与后续验证

- 没有跑真实歌曲的端到端 GPU 合成，实际错词修正后的听感需在使用中检查。
- 模糊匹配是可确认候选，不是自动校正保证；极端错词、重复段落或不同演唱版本仍可能需要手工定位。
- 跨 SYN 的时间依据当前按同一参考关联，尚无独立的歌曲版本/编排坐标组管理界面。
- 首版没有自动联网搜索歌词、LRC 时间标签导入或后台匹配 worker。
- 草稿随工程保存，不另建独立自动保存系统；使用现有保存命令保存进度。
