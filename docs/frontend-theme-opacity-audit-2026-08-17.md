# 前端主题与不透明度审计

日期：2026-08-17  
状态：已完成首轮修复，等待人工验收
审计工程：`V5P Editor Dev`  
审计页面：主页、Timeline、设置、键位教学、显存管理、合成单元编辑器及其浮层

## 1. 结论先行

当前并不是某几个颜色写错，而是同时存在三套没有统一的样式系统：

1. 工作台自己的 `--app-*` 主题变量，支持 Night、Light、奶黄。
2. Naive UI 的默认浅色主题与默认绿色强调色。
3. 合成单元编辑器及其弹窗中写死的夜间色板。

不透明度数值本身没有写反。设置中的 `0.2` 确实会生成 `20%` 的背景不透明度，因此“中栏不透明度”等名称在语义上是正确的。真正的问题是作用边界不一致：有些底层面板跟随不透明度，有些子面板、编辑器、右键菜单和传送到 `body` 的浮层完全不跟随，另一些浮层又直接变成 20% 而失去可读性。

本轮共记录 12 项，其中 8 项已在实际页面复现，4 项由相同代码路径直接确认。

### 2026-08-17 修复结果

- 已建立全局 Workbench Palette 与 Naive UI Theme Bridge。
- 主题变量已提升到全局根，Teleport 浮层可以继承主题。
- 首页、键位教学、显存页、RenderPanel、H Token Picker、合成单元编辑器及其 Modal/Popover 已接入主题。
- 中栏编辑器底板、标签、TrackHeader、SYN 网格和 Inspector 已跟随中栏不透明度。
- 顶栏与状态栏共用同一不透明度设置。
- 浮层不再机械继承 20% 的区域不透明度，统一采用 94% 可读底色；毛玻璃仍跟随对应区域。
- Timeline 对象菜单固定为 196px，并加入视口边缘钳制；资源树与音轨头菜单也加入边缘钳制。
- 首页恢复可滚动，项目较多时不会被全局 `overflow: hidden` 截断。

以下正文保留为问题发现时的证据与验收依据。

## 2. 严重问题

### UI-01：Naive UI 没有接入应用主题

严重度：高  
确认方式：实际页面复现 + 代码确认

现象：

- Night 主题下，`NInput`、`NInputNumber`、`NSelect` 等仍是大块白色控件。
- “文件”下拉菜单在 Night 和奶黄主题下仍是纯白背景。
- Naive UI 的主按钮、滑杆、开关仍使用默认绿色，而应用主题强调色分别是蓝色、蓝色和棕色。
- 首页的删除确认浮层是白色，与固定夜间首页直接冲突。
- 合成单元编辑器虽然是深色，内部 Naive UI 输入框仍是白色。

根因：

- `client/src/main.ts` 只挂载 Pinia 和 Router，没有全局 `NConfigProvider`。
- 应用主题只通过 `ProjectPage.vue` 的 `.app-root` CSS 变量实现，Naive UI 不认识这些变量。
- Naive UI 的下拉、Popover、Modal 等通常挂到 `body`，更不可能继承 `.app-root` 的局部变量。

影响范围：

- `TopBar.vue`
- `SettingsPage.vue`
- `RenderPanel.vue`
- `GpuRuntimePage.vue`
- `SynthesisUnitEditor.vue`
- `HTokenPicker.vue`
- `HomePage.vue`
- `TrackHeader.vue` 中的 `NColorPicker`

建议方向：建立唯一的 Theme Bridge，由当前 WorkbenchTheme 同时生成应用 CSS 变量、Naive UI theme 和 themeOverrides。不要继续逐组件覆盖 Naive UI 的内部类。

### UI-02：音轨头右键菜单实际没有背景

严重度：高  
确认方式：实际页面复现

复现：奶黄主题，任意不透明度，右键音轨左侧的音轨头。

现象：

- 菜单背景透明，可以直接看到后面的音轨按钮和文字。
- 菜单文字回退为夜间主题的浅灰色；在奶黄或 Light 主题上对比度很差。
- 菜单内的颜色选择器仍是 Naive UI 默认浅色外观。

根因：

- `TrackHeader.vue:298` 使用 `<Teleport to="body">`。
- `.ctx-menu` 在 `TrackHeader.vue:431` 使用 `var(--app-panel)`、`var(--app-border)` 和 `var(--app-text)`。
- 这些变量只定义在 `.app-root`，Teleport 后的节点位于 `.app-root` 外部，变量未定义，相关 CSS 声明失效。

这是确定的样式 bug，不是低不透明度造成的视觉错觉。

### UI-03：合成单元编辑器完全写死为夜间主题

严重度：高  
确认方式：实际页面复现 + 代码确认

现象：Light 或奶黄主题中打开 SYN，左右区域保持亮色/奶黄，中间编辑器整块突然变成深黑色。

根因：

- `SynthesisUnitEditor.vue:3742` 开始的整套编辑器样式大量直接使用 `#101419`、`#171c22`、`#11161b`、`#5dc9b1` 等固定颜色。
- 该组件没有消费 WorkbenchTheme，也没有主题类或语义化色板。

附带影响：

- 编辑器不响应“中栏不透明度”。
- 编辑器不响应“中栏毛玻璃”。
- 主题切换后，编辑器、外层标签栏和右侧 RenderPanel 分属三种视觉系统。

待审核规则：需要决定“合成单元编辑器必须跟随全局主题”，还是“它是固定暗色专业编辑面板”。即使选择固定暗色，也必须处理 Naive UI 白色控件及与外层的过渡，不能维持当前半跟随状态。

### UI-04：多个 Modal/Picker 被强制成夜间卡片

严重度：高  
确认方式：代码确认；CFG Popover 已实际复现

现象：Light/奶黄主题下，以下浮层仍是固定深色卡片：

- Segment 编辑
- Kana 编辑
- MIDI-P 替换
- 本句 MIDI-P 重提取
- 覆盖确认
- 显存容量确认
- H Token Picker
- CFG 高级采样控制

代码证据：

- `SynthesisUnitEditor.vue:3844`
- `SynthesisUnitEditor.vue:4276-4286`
- `HTokenPicker.vue:135`
- `RenderPanel.vue:565`

这些深色容器内部又混有 Naive UI 默认白色输入框，导致一个弹窗内部也存在两套主题。

## 3. 不透明度问题

### UI-05：三个不透明度控制的作用边界不一致

严重度：中高  
确认方式：实际页面复现 + 代码确认

实际验证：把中栏、左右栏、顶栏均调到 `0.2`，根变量会正确变成 `20%`。数值计算没有问题。

不一致之处：

- 中栏底色、Timeline Canvas 底色会变为 20%。
- 激活的编辑器 Tab 仍使用完全不透明的 `var(--app-panel)`。
- TrackHeader 仍使用完全不透明的 `var(--app-panel)`。
- Timeline 内联文字编辑器仍完全不透明。
- 合成单元编辑器整体完全不透明。
- 状态栏始终使用完全不透明的 `var(--app-panel)`，没有任何关联设置。
- 左右栏只有容器底色变透明，Naive UI 输入框、选择器、Tag 等仍保持不透明。

关键代码：

- `EditorWorkspace.vue:65,76,99`
- `TrackHeader.vue:315`
- `TrackCanvas.vue:1847,1878`
- `RenderPanel.vue:462`
- `StatusBar.vue:51`

待审核规则：需要先明确不透明度控制的是“区域底板”还是“区域内所有 surface”。当前实现介于两者之间，用户无法预测哪些部分会透。

### UI-06：顶栏下拉菜单不跟随顶栏主题与不透明度

严重度：中  
确认方式：实际页面复现

现象：顶栏设为 20% 后，“文件”菜单仍为 100% 不透明的 Naive UI 白色菜单；奶黄主题下也仍是白色。

根因：下拉菜单由 Naive UI Teleport 到 `body`，既没有应用主题，也没有顶栏浮层不透明度策略。

建议方向：浮层不应该机械继承顶栏 20%，但必须有明确的统一规则。例如主题跟随全局，浮层底色最低保持 85%-95% 不透明，以保证文字可读。

### UI-07：资源树和 Timeline 对象菜单在低不透明度下难以阅读

严重度：中  
确认方式：实际页面复现

现象：

- 资源树菜单直接使用左右栏不透明度。
- Timeline 对象菜单直接使用中栏不透明度。
- 当设置为 20% 时，菜单背景也是 20%，底下的对象和文字明显穿透。
- 菜单 hover 背景却使用完全不透明的主题色，悬停前后透明度跳变很大。

代码：

- `LeftSidebar.vue:37-46,740-757`
- `TrackCanvas.vue:135-144,1812-1833`

这项需要产品规则确认。建议把“工作区面板不透明度”和“浮层可读性不透明度”分离，浮层不低于一个固定下限。

### UI-08：毛玻璃开关覆盖范围与不透明度覆盖范围不一致

严重度：中  
确认方式：代码确认

现象：

- 中栏毛玻璃只挂在 `.editor-workspace`，但合成单元编辑器等内部完全不透明 surface 会把效果全部遮住。
- 左右栏手写的资源树和 Timeline 菜单能单独获得 blur，Naive UI 浮层和音轨头菜单不能。
- 顶栏有不透明度设置，却没有对应的毛玻璃策略。

结果是同一组外观设置在不同页面上的视觉效果差异很大。

## 4. 其他主题与样式错误

### UI-09：首页永远是 Night，忽略已保存主题

严重度：中高  
确认方式：实际页面复现 + 代码确认

复现：项目内切换为奶黄主题，回到首页。首页仍为固定夜间主题。

根因：

- `HomePage.vue:133-155` 全部使用硬编码夜间颜色。
- UiSettings 只在 ProjectPage 创建 `.app-root` 时接入，首页没有主题根节点。
- `App.vue` 和 `body` 也固定为 `#0d1117`。

如果首页确实要固定夜间品牌样式，需要在产品规则中明确；否则它应跟随持久化主题。

### UI-10：主题变量只存在于 `.app-root`，所有 body 浮层都很脆弱

严重度：中高  
确认方式：代码确认，音轨头菜单已实际触发

现状：

- Night/Light/奶黄变量定义在 `ProjectPage.vue:322-369` 的 `.app-root` 与主题子类。
- `body` 只有固定夜间背景和文字色。
- 任何 Teleport 到 `body` 的手写浮层，只要引用 `--app-*` 就会丢失变量。

UI-02 已经是这个结构问题的直接结果。后续新增 Modal、Tooltip、Dropdown 时还会继续重复。

建议方向：主题语义变量至少应放到稳定的全局主题根，或由 Teleport 容器统一承载主题类，不能依赖每个浮层手工复制颜色。

### UI-11：键位教学页使用固定青绿色，Light/奶黄下对比度过低

严重度：中  
确认方式：实际页面复现

现象：奶黄主题下，章节序号、操作列和步骤边框仍使用偏浅的 `#5dc9b1`、`#8ed8ca`、`#9bcabb`，与浅色背景对比度很低，也与奶黄主题的棕色强调色冲突。

代码：`KeymapHelpPage.vue:180,196,223,228`

建议方向：这些是界面强调信息，应使用 `--app-accent` 或从主题派生的可读强调色，而不是合成编辑器的固定青绿色。

### UI-12：Timeline 对象右键菜单会异常横向拉宽

严重度：中  
确认方式：实际页面复现

实际记录：在 1280px 宽窗口中，从 `x=700` 打开菜单，菜单宽度约 `429px`，一直延伸到右侧 RenderPanel；设计的 `min-width` 只有 `148px`。

相关样式：`TrackCanvas.vue:1812-1833`

可能原因：fixed 定位元素宽度为 auto，而子按钮 `width: 100%` 参与 shrink-to-fit 计算，最终吸收了右侧可用宽度。

建议方向：为菜单给出稳定宽度或 `width: max-content` + 合理的 min/max-width，并做视口边缘翻转/钳制。

## 5. 建议修复顺序

1. 建立全局主题根与 Naive UI Theme Bridge，先解决 UI-01、UI-02、UI-10。
2. 明确“不透明度控制的是哪些 surface”以及“浮层最低不透明度”，再统一修 UI-05、UI-06、UI-07、UI-08。
3. 决定合成单元编辑器是全局跟随还是固定暗色专业界面，再统一改 UI-03、UI-04，避免边修边推翻。
4. 修首页和键位教学的主题继承，即 UI-09、UI-11。
5. 单独修 Timeline 菜单尺寸，即 UI-12。
