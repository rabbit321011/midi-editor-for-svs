# ver0.9 歌词辅助校对首版落地报告

> 状态：首版代码完成，针对性测试与浏览器交互检查通过；未运行 GPU 合成验证。
> 设计基线：[design.md](design.md)。实施前设计提交：`6a0b652`。
> 本报告只覆盖本轮歌词校对和罗马音显示改动，不覆盖工作区已有的模型等其他改动。

## 1. 用户入口与操作

SYN 编辑器工具栏新增书本图标“歌词辅助校对”。SYN 尚无 Segment 时入口禁用。

1. 首次进入，选择工程已有参考，或一次粘贴整首/一段歌词。
2. 选择 Segment，临时浮层显示当前文字、读音及匹配候选。点击候选后填入草稿。
3. 原文和读音可以手改。改原文后必须重新生成或明确确认保留读音，避免原文正确而读音仍旧。
4. “确认并继续”保存校对草稿，尚不覆盖 Segment；“跳过”可在后续待处理导航中返回。
5. 从列表图标打开修改预览，将当前有效、已确认的草稿一次应用。可撤销和重做。
6. 改了读音的句子显示控制待更新，可显式重新对齐 Kana 或按修正 Segment 更新 H。

只有复杂操作才展开参考全文与相邻片段弹窗。没有新增常驻侧栏或歌词轨；空间不足时使用临时弹窗。当前句周围试听、相邻片段联合试听均不改变 Segment 边界。

## 2. 已落地的匹配与时间关系

- 按参考文字范围匹配，不按歌词行分配，支持跨行与半句。
- 使用原文、假名读音的宽松子串匹配，容忍一定插入、删除和替换。
- 利用前后识别文字、已经确认的相邻范围，以及相同参考下其他 SYN 的时间定位给候选排序。
- 实际时间由实例 timelineStart 与 Segment frame/frameRate 相加；没有实例时只使用相对时间。
- 时间线实例的完整时长需与 Guide 时长相符，否则不套用简单加法。
- 同一源 SYN 的不同实例分别保存确认位置；新复制的实例不会自动继承旧位置。
- 保留重复歌词候选，允许同一参考范围被重复引用，也允许暂不确定位置而先确认文字。
- 参考版本、Guide 与 Segment 内容/边界变更会使旧草稿需要复核；无效草稿不混入有效子集的批量应用。

当前使用有余量的局部排序加全文兜底，而非严格禁止范围外候选。位置余量为至少 16 个原文索引单位，随当前句长度增加；跨 SYN 时间候选容忍 1.5 秒偏差；最多显示 8 个排序候选。这些是首版启发式参数，不是经过真实歌曲集校准的准确率承诺。

## 3. 数据与读音

工程对象树新增可选 lyricProofreading 数据，保存参考歌词及版本、各 SYN 会话、草稿和实例定位。数据随现有工程保存/加载流程持久化。旧工程没有该字段时仍正常打开。

文字校对写回源 SYN，引用它的时间线实例共同看到更新。预览显示实例共享关系。应用保持 Segment ID、起止 frame、MIDI-P、Guide 和历史 Take 不变。

新增 CPU 读音接口 `POST /api/lyrics/reading`，使用现有 Whisper Python 环境中的 Sudachi 和 jaconv，不加载 Whisper 或 GPU 模型。返回参考文本的 UTF-16 范围与假名读音。转换不可用时仍可保存参考并手工填写读音。

字符引用与发音分配可以不同：读音匹配落在词语内部时保留整词参考范围，草稿读音可以只取实际唱出的部分。相邻段通过切换当前段分别校对，没有新增同时编辑多段时间边界的工具。

## 4. Kana/H 更新

原文改写但读音不变时不要求重算 H，并保留已有 Romaji。读音变化则保留待更新状态；保存文字并不表示合成控制已经更新。

更新按钮复用现有 Segment -> Kana/H 入口及 GPU 容量、版本校验和手工覆盖确认。进入该流程时关闭校对浮层，避免遮挡原有确认窗口。只在覆盖范围与修订来源符合条件的 Segment -> H 操作后解除对应提示；清空 H 不能冒充完成更新。

没有自动执行整首对齐，也没有新增批量 GPU 队列。

## 5. 显示罗马音

设置新增“歌词显示 -> 显示罗马音”，默认关闭。

- 影响 SYN Segment/Kana、其检查栏和编辑框、校对浮层与预览，以及旧文本轨/文本编辑器。
- 仅控制显示；隐藏不删除已有 Romaji，Kana 与 Romaji 的原有数据转换仍保留。
- 使用 `GET/PUT /api/ui-preferences` 读取与保存，持久化到后端 `server/data/ui-preferences.json`。
- 该开关不写入浏览器 localStorage，启动时以后端值为准，跨工程共用。
- 保存期间禁用开关；写入失败保持上次成功值并在设置页显示错误，提供重新读取入口。
- “恢复默认”也将关闭状态写到后端。

现有主题、透明度等其他偏好仍使用原来的存储方式，本次没有整体迁移设置系统。

## 8. 限制与后续验证

- 没有跑真实歌曲的端到端 GPU 合成，实际错词修正后的听感需在使用中检查。
- 模糊匹配是可确认候选，不是自动校正保证；极端错词、重复段落或不同演唱版本仍可能需要手工定位。
- 跨 SYN 的时间依据当前按同一参考关联，尚无独立的歌曲版本/编排坐标组管理界面。

- 草稿随工程保存，不另建独立自动保存系统；使用现有保存命令保存进度。

## 9. 首轮使用反馈修正

- 修正全角空格被 Sudachi 读为キゴウ的问题：后端转换跳过空白/辅助标点 token；前端按原文范围过滤已缓存的格式 token。真正的“記号”读音保留，已应用的 Segment 不自动替换，需重新生成读音并确认应用。

- 同一位置仅起止范围稍有不同的候选合并为一个最佳结果，候选区明确标为“匹配位置”；位于不同位置的重复副歌仍分别保留。
- 罗马音开关补充覆盖匹配候选和参考全文。全文按原始行显示原文及对应罗马音，关闭开关后只显示原文。
- 全文使用可选取原文的显示组件替代纯文本框，选取和复制始终映射回原始 UTF-16 范围，不把展示用罗马音写回歌词；保留跨行选取、当前范围高亮和定位滚动。
- 缺少参考读音时显示“生成参考读音”入口，避免把无读音误认为开关失效。
- 参考全文的罗马音按读音 token 与原文范围同步高亮，支持跨行与手工选取；候选罗马音也高亮对应内容。汉字与读音无法逐字对应时，以对应词的读音 token 为单位，不按字符串长度比例猜测。
- 校对针对性测试增至 16 个，新增相近候选合并、重复位置保留、逐行读音/原文偏移及跨行读音高亮验证。无头浏览器检查了候选与全文罗马音显示/高亮，以及跨行选取后只应用原文的流程。

## 10. Kana 硬边界 H 对齐修正（2026-09-29）

- 失败样本“うつむきかげんにきょーもくちごもる”的原始锁定序列为 29 个 Token，与 SOFA 的 29 个音素直接映射完全一致。对齐前端再次将读音规范为片假名并运行 G2P 时得到 31 个 Token，其中 `kj` 变成 `k i j`，触发 `phone_ipa_length_mismatch`。这不是已修正的“きごう”残留，也不是声学预测漏了两个音素。
- 工作台的 `v5p_compile_text_control.py` 在 Kana 硬边界模式增加严格的直接映射恢复：仅处理前端序列校验失败，且必须满足原始锁定 Token、候选 Token、SOFA 直接映射 Token 和当前词表逐项一致；音素与 mora 声学匹配均须为 exact，区间有效，mora 标签与输入 Kana 对应。
- 不扩展、删减或替换模型输入 Token，不修改训练包、词表及其哈希契约，不移动用户 Kana 边界。恢复后仍执行单调落帧、Kana 窗口容量和最大 4 帧偏移限制；未知映射、声学错误及空间不足继续拒绝，不回退为 PUL。
- 输出 `hAudit.phraseModes[].tokenBridge` 记录恢复方式 `direct_locked_exact` 和原始失败原因；原始前端诊断保留，不能将此恢复解释为规范化 G2P 序列已一致。
- 11 项 H 编译测试通过，包括恢复后 Token/边界不变、8 类不可信映射拒绝以及窗口容量不足拒绝。使用上述实际失败记录进行 CPU 编译回放：29 个歌词事件、16 个 Kana、最大偏移 1 帧、无 PUL，原始 Token 哈希不变。未重新运行 SOFA GPU 推理或音频合成，未修改用户工程或原始失败记录。

## 11. Segment 转录异常隔离（2026-09-29）

- 排查时前端仍运行，但后端 8101 无监听；用户日志显示 GPU 状态、F0、工程 blob 接口同时 `ECONNREFUSED`。最近两个 Whisper 任务仅有上传音频，无转录输出。该日志证明后端不可达，但不足以确定首次转录失败原因。
- 发现 `/api/whisper/run` 非等待式启动的 `runWhisper` 仅捕获初始化校验错误，未捕获后续 Whisper、运行时释放和 SOFA 阶段的异步拒绝。将整个流水线纳入任务级异常处理，避免分析失败成为未处理的 Promise 拒绝并导致服务退出。
- 非常驻 Whisper 子进程失败时保留原始结构化错误或最多 6000 字符的 stderr 尾部，终端日志附带任务目录名，避免仅留下通用退出码。
- SYN 重命名只更改显示名，转录音频按 Guide asset ID 定位，输出名经过字符过滤；目前没有证据表明本次由改名引起。
- 3 项 Whisper 服务测试及后端 `tsc --noEmit` 通过。新增测试使用非 Python 解释器制造真实子进程失败，验证流水线不再向调用方抛出未捕获异常并保留诊断，不加载模型、不访问网络、不使用 GPU。开发文件监听自动恢复后端后，健康接口返回正常；尚未重新执行实际转录。

### 后续确认：VAD 将整段音频过滤为空

- 重试日志显示 `Whisper returned no Japanese phrases`，发生于常驻 Whisper 的文本阶段，尚未进入 SOFA 对齐。
- 对失败任务 `render_e69703d7_whisper` 的实际上传音频检查：44.1 kHz 单声道、14.2056 秒、峰值约 0.662、RMS 约 0.106，并非全静音。用本机 faster-whisper 的音频解码及默认 VAD 参数做 CPU 回放，得到空人声区间列表、保留时长 0 秒，确认本次前置 VAD 全段过滤。
- 两条 Whisper 路径共用 `transcribe_segments`：仅在启用 VAD、无非空转录且 `duration_after_vad == 0` 时，关闭 VAD 重试一次。保留解码参数和 Whisper 自身无语音判断；不重试运行时异常，也不对正常结果或已关闭 VAD 的请求额外重试。再次为空则明确提示检查 Guide 中的人声，不编造占位歌词。
- 7 项 Whisper/SOFA 轻量测试通过，覆盖恢复路径、重试边界和失败退出。未再次运行 GPU 转录，不能据此保证该音频必定识别成功。已加载的常驻 Whisper 需要释放并重新加载才能读取更新后的脚本。

## 12. MIDI-P 八度快捷键（2026-09-29）

- 点击 MIDI-P 音符或其 FLOW 延续帧，选中整颗音符并聚焦 MIDI-P 区域；Ctrl 点击可追加选择或取消选择，普通点击恢复单选。选中高亮覆盖音符头及其 FLOW。
- MIDI-P 区域获得焦点时，Ctrl + 上/下方向键将所选音符整体升高/降低一个八度，即 class 加减 24。也兼容 Meta 修饰键。不处理 Alt/Shift 组合和按键自动重复，避免长按意外连续跳跃；输入框和其他区域不触发。
- 保留 FLOW、音符起止时间和音程关系，不改动其他控制轨；同音高但不同音符头的相邻音符仍独立处理。任何音符超出 class 0..254 时整次拒绝，REST/PAD 不参与升降。
- 批量修改形成一个 MIDI-P revision 和一个撤销记录，可用 Ctrl+Z 撤销、Ctrl+Shift+Z 重做。修改标为手工编辑；MIDI-P 播放中刷新试听，否则试听所选第一颗音符。
- 20 项控制轨事务测试及前端类型检查通过。独立无头浏览器的临时工程验证了 FLOW 选择、单选/多选升降、撤销/重做和焦点隔离；拦截工程保存，不修改用户工程。未增加面板或音色功能。

## 13. MIDI-P 试听失效修正（2026-09-29）

- 复现路径：先生成并试听 MIDI-P，再操作 Kana/Segment 文本相关编辑，之后 MIDI-P 试听无声。
- 根因是 Kana 边界拖动结束处理同时调用 `stopScheduledMidiNodes()` 和 `midiAudioContext.close()`。前者只应清除当前排程节点，后者却销毁了后续试听要复用的 AudioContext；即使没有实际移动边界，点击结束也可能触发关闭。
- 已移除编辑操作中的 `midiAudioContext.close()`。工作台真正卸载时仍会关闭上下文；日常编辑只停止排程节点，下一次试听会正常复用或创建可用上下文。
- 使用浏览器临时工程复现并验证：MIDI 试听后点击 Kana 边界，AudioContext 保持运行，随后再次点击 MIDI 音符可继续试听。20 项 MIDI 控制事务测试和前端类型检查通过；未修改用户工程。

## 14. 可选 MIDI 试听音色（2026-09-29）

- 设置页新增 MIDI 试听音色下拉菜单：钢琴、柔和电子音、方波。沿用浏览器本地偏好持久化，默认柔和电子音，不改变现有用户默认听感。设置同时作用于主时间线与 SYN 编辑器，切换后播放中的 MIDI 重新排程。
- 新增共享 MIDI 发声模块，钢琴使用 30 个本地 Salamander MP3（约 2.01 MB），覆盖 A0 至 C8，其他音高通过最近采样变速实现，保留 MIDI-P 的 50 cents 精度。这是单层试听音源，不包含原版力度层、踏板和共鸣系统；特别长的音符会随采样自然衰减。
- 采样固定来自 Tonejs/audio 提交 `efd8296360f9526e379bfbe5c1698ff54d6a1d34`，未改动源 MP3，附原始 README、CC BY 3.0 署名说明及 SHA-256 清单。下载脚本可复现资源，但正常使用无需再次下载。
- 首次钢琴播放先加载采样再启动时钟；加载失败明确提示，允许再次尝试。两处播放共用发声包络，轨道音量/M/S 与音符包络分离，避免改音量时破坏音符收音。音符结束后断开节点，停止/切换时取消待播放预览。
- 完善上一节试听生命周期修复：Kana 边界编辑不再停止 MIDI 排程；编辑器卸载时才关闭并清空 AudioContext，遇到已关闭上下文可以重建。不会修改 Guide、歌词、MIDI-P 数据或 AI Take 音色。
- 37 项针对性测试通过。浏览器用真实采样做离线 PCM 渲染，三种音色均非静音、单音不削波、结束后为静音，钢琴音量为 0 时输出为 0；设置切换、持久化和 SYN 钢琴采样发声验证通过。未跑 GPU 合成。

## 15. 三路 CFG 开关与范围（2026-09-30）

- Pg 路线仅对本次生成的 B 区 MIDI-P 做 class 加减 `2*半音数`，REST、A、gap/rear、H 和所有时间边界不动；越界时整次拒绝，不截断音符。F1 沿用其独立 PAD=256 零 embedding 语义，并仅移调一次。
- Sg 复用现有 Rubber Band 音频移调工具，在采样前生成 B Guide 临时副本，保留共振峰并明确 pad/trim 到原采样点数。副本经采样率/帧数/采样点数/hash 校验后供各参考的 SOME 条件提取；A 的原始 VAE 输入不变。0 不生成副本。
- 原素材快照不被改写；移调值与副本身份冻结进完整 job manifest，副本绑定原 Guide hash，结果的 samplingSettings 必须与服务端冻结参数一致。旧工程/请求缺少参数时保持 0 的原有行为，非法值及不匹配副本明确拒绝。
- 相关 CPU/服务端/前端测试、类型检查及浏览器验证通过；真实 Rubber Band 的 +/-12 半音测试输出频率接近 880/220 Hz，两个副本均保持 65,536 samples / 44.1 kHz，原 440 Hz Guide 的文件哈希不变。
- 本次未额外运行模型 GPU 合成或歌曲听感实验，未修改用户工程，也未提交 GitHub。详细合同见 [melody-transpose.md](../../melody-transpose.md)。
