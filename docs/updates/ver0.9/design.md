# ver0.9 SYN 歌词辅助校对设计

> 状态：设计稿，尚未实现。本文不代表当前软件已具备这些能力。
> 范围：现有 SynthesisUnit 编辑器内的歌词定位、校对和局部控制数据更新。
> 本文整理本轮讨论已确认的原则；数据结构建议和算法参数仍需在实现时验证。

后续状态：首版已实现，实际能力、实现取舍及验证范围见 [落地报告](report.md)。上面的状态描述保留为实施前设计基线。

## 1. 用户问题与目标

Whisper 识别的歌词有时存在错字、漏字、多字或读音错误。当前用户需要离开工作台查找正确歌词，再逐段复制，维护原文、Kana 和 Romaji，并处理后续 Kana/H 对齐。长歌词、重复副歌和不规则 Segment 切分会增加定位成本。

目标是让用户找到一次正确歌词后，尽量留在工作台里完成当前 SYN 的校对。工作台应帮助定位对应文字、提出修正候选和保留进度，而不是把整首歌词列表摆出来，让用户自行逐句查找。

核心体验：选中片段 -> 定位参考文字 -> 试听和确认文字/读音 -> 连续处理下一段 -> 查看修改 -> 显式应用及更新需要重做的控制数据。

不要求用户为了辅助匹配而重新切句，不新增常驻侧面板或歌词轨道，不把当前工程当成单轨 MIDI 填词工具。

## 2. 当前项目的实际基础

以下是设计依托的现有结构，不是本版本新增功能：

- 源 SynthesisUnit 包含 Owned Guide、SegmentTrack、KanaTrack、HTokenTrack、MidiPTokenTrack 和 Takes。
- 时间线 TrackObject 引用源对象；源 SYN 与时间线实例需要区分。
- Segment 保存原文、Kana、Romaji、startFrame 和 speechEndFrameExclusive。
- Whisper + SOFA 可以生成 Segment，也有单个 Segment 重新转录入口。
- Segment 编辑框中，Kana 与 Romaji 可以互转；原文输入不自动同步读音。
- 文本对齐输入优先使用 Segment.kana，缺失时才使用 Segment.text。
- 修改 Segment 不会自动重写独立的 KanaTrack 和 HTokenTrack。
- 已有从 Segment 对齐 Kana/H、按当前 Kana 边界对齐 H 的操作，以及覆盖手工数据的确认机制。

## 3. 已确认的设计原则

### 3.1 参考歌词服从时间线边界

时间线已有 Segment 的起止边界是本功能的基准。参考歌词的换行、句号、词语边界均不是强制切分依据。

允许一行参考歌词对应多个 Segment，也允许一个 Segment 对应参考歌词的半行、多行或词语的一部分。自动候选和人工修正均只调整参考文字及读音的分配，不修改 Segment 起止 frame。

“连同相邻段校对”只扩大查看、试听和文字分配范围，不合并 Segment，不改变 Guide，不重切时间线。对齐失败或文字分配困难时保留待处理状态，不要求用户移动边界来完成辅助校对。

### 3.2 参考文本共用，写入目标明确

工程可保存多份参考歌词。同一份歌词可以供多个 SYN 使用，但每次校对都明确针对一个源 SYN 的具体 Segment。

批量确认不默认修改其他 SYN、整条音轨或整个工程。相同源 SYN 被多个时间线实例引用时，源 Segment 修改会被这些实例共享；预览应说明这一实际影响，不能宣称只修改了一个实例。

### 3.3 确认结果构成时间定位依据

确认对应关系后，将 Segment 的相对时间与当前 SYN 时间线实例的位置结合，得到实际时间范围。用它辅助定位其他 Segment 和同一演唱编排中的其他 SYN。

用户确认是强依据，自动生成但未经确认的候选是弱依据。不能让一串未经确认的猜测相互强化并变成“已确认”。

### 3.4 容忍误差，不追求完全相等

文字比较需要容忍识别错误、汉字/假名差异及分句偏差；邻段约束和时间约束都应留余量。先局部搜索，再按需要扩大范围，而不是把当前段硬塞进一个严格区间。

### 3.5 不挤占时间线

日常只保留紧凑入口。校对状态利用现有 Segment 外观，普通操作使用临时浮层，复杂操作使用可关闭的弹窗。不得新增常驻侧栏、常驻底部区域或参考歌词轨道来压缩时间线。

## 4. 用户操作流程

### 4.1 准备参考歌词

用户点击工具栏的辅助校对入口，通过弹窗选择工程中已有的参考歌词，或粘贴整首/一段歌词。参考歌词保存原始换行，便于阅读，并记录版本。

这一步不修改 Segment，不启动 Whisper 重转录，不更新 Kana/H。首次导入后关闭弹窗，恢复完整时间线空间。再次进入时沿用已选参考和进度。

第一版以粘贴和工程内复用为必需入口。歌词网站搜索、自动抓取、TXT/LRC 导入属于扩展能力，不作为完成本设计的前提。

### 4.2 选择当前片段

用户点击已有 Segment，或者从待处理的第一段开始。工作台使用当前段、邻段上下文、已确认定位点和实际时间寻找候选。

找到候选后，浮层只展示当前识别、建议文字、读音和必要的附近上下文。对应范围可以跨参考歌词行。全文默认不展开，不让用户滚动长列表寻找当前句。

### 4.3 试听并确认

浮层提供当前段试听，以及可选的带前后文试听。扩大试听范围不改变任何对象边界。

原文和读音是主要编辑内容，Romaji 为辅助查看内容。用户可以修改候选原文和读音，或接受候选后进入下一段。

“确认并继续”写入本轮校对草稿，不立即改写正式 Segment 或运行模型。草稿和进度随工程保存。浮层需要明确区分“已确认待应用”和“已应用”，避免用户误以为确认就已影响合成。

### 4.4 纠正定位

用户点击“其他候选”或“位置不对”，打开扩展弹窗。弹窗展示候选所在的参考文本上下文、出现次序和当前对应范围。

用户可以搜索听清的文字，也可以在全文选取一个范围，指定为当前段的参考。确认后将该关系作为后续匹配的定位依据。

系统不得编造“主歌”“第二副歌”等段落名称；只有参考文本明确标注时才可使用，否则使用出现次序和前后文。

### 4.5 跨 Segment 调整文字分配

当一个词或句子被多个 Segment 切开时，用户可以把相邻段加入同一次校对。弹窗显示每段现有时间和拟写入的原文/读音，支持逐段试听及联合试听。

示例：参考歌词为“君の声が聞こえる”，实际切分要求如下。

```text
Segment 1：君の声が聞こ
Segment 2：える
```

调整的是参考文字分配点，不是音频边界。不能按字符数、时长比例或 MIDI 音符数直接平均分配后视为确认。

汉字对应多个发音单位且切点位于其内部时，允许两个 Segment 关联同一参考词的不同读音部分。原文引用范围和实际发音分配分别记录；不要求用户把汉字生硬拆开，也不要求移动时间边界。

### 4.6 连续校对与恢复

紧凑工具栏提供已检查/总数和前后待处理导航。允许暂时跳过，随后仅遍历待处理项。

跳转下一段时保持时间轴缩放，必要时最小幅度滚动到目标。切换 SYN 后参考歌词可复用，但对应位置、候选、草稿和进度分别恢复，不能沿用上一 SYN 的阅读位置。

### 4.7 查看修改并应用

用户在修改预览弹窗中检查所有拟写入的内容，区分仅原文变化、读音变化、分配未确认和需要更新控制数据的句子。

未解决项保留，不被强制提交。可应用已确认的子集，不要求整份 SYN 全部通过后才能保存。应用作为可撤销的事务，保持 Segment ID 和边界不变。

保存文字与更新 Kana/H 是不同动作。用户可以只保存文字，也可以明确选择继续更新受影响范围。涉及手工控制数据时显示实际将覆盖的范围及数量。

## 5. 时间定位与跨 SYN 复用

### 5.1 时间计算

对于没有额外播放变换、使用完整 SYN 的时间线实例：

```text
segmentRelativeStart = startFrame / frameRate
segmentRelativeEnd   = speechEndFrameExclusive / frameRate
absoluteStart = instance.timelineStart + segmentRelativeStart
absoluteEnd   = instance.timelineStart + segmentRelativeEnd
```

使用 SYN 自身 frameContract，不硬编码帧率。内部保存精确值，显示时可以舍入。区间按半开区间处理。

实例若支持裁剪、拉伸等额外变换，实现时必须复用真实播放映射；上述简单加法不能无条件套用。无可靠映射时只使用局部相对时间，不制造绝对定位点。

### 5.2 定位关系的归属

文字校对归属源 SYN/Segment；绝对时间定位关联具体 TrackObject 实例。相同 SYN 在不同位置出现时，分别计算实例时间，不把多个演唱位置折叠为一个时间戳。

从资源树打开、尚未放入时间线的 SYN 仍可完成本地文字校对，但不向全局提供猜测的时间定位。历史来源时间或默认导出位置不能冒充当前实例的实际时间。

### 5.3 定位依据的共享条件

已确认的“实际时间范围 <-> 参考歌词范围”可帮助同一参考、同一演唱时间坐标中的其他 SYN。相近时间和相同歌词不意味着必然属于同一声部内容，仍要结合当前音频文字和上下文。

混有不同歌曲、不同编排或不同音频版本时，不默认共享所有定位点。第一版可以仅在明确使用同一参考的 SYN 中提出跨 SYN 时间候选，并保留来源信息；出现矛盾时退回局部匹配。

有部分已确认 Segment 的 SYN 即可贡献局部定位点，不必等待整份 SYN 通过。整份通过仅是用户进度状态。

### 5.4 编辑后的维护

- 移动时间线实例：重算绝对时间；保留文字关系，重新评估依赖其时间的未确认候选。
- 删除实例：移除该实例的时间定位；保留源 SYN 文字草稿。
- 复制实例：新实例有独立定位身份，不能直接继承旧实例的重复段落判断。
- 改动 Segment 文字、读音或边界：对应确认标为需复核；边界改动仅指用户在本功能之外的主动编辑。
- 更换 Guide、重转录或删除 Segment：原关系不静默挂到新段上，根据源版本标记失效或待重新匹配。
- 改动参考歌词：创建新版本，旧范围关联保留版本信息；重新定位前不将旧字符偏移直接应用到新文本。

## 6. 候选匹配规则

### 6.1 参考歌词不是按行消耗的列表

匹配对象是参考文本范围及其读音范围，不是行号。保留原文、换行和显示位置；匹配用的规范化文本需要能映射回原文，不能清洗后丢失高亮位置。

参考范围可重复引用，允许相邻 Segment 在参考词层面重叠。重复使用不算冲突，不能用“已经分配过”阻止第二遍演唱。

### 6.2 优先使用已确认的邻段

当前段前后都有已确认关系时，以两端之间及适当扩展的范围作为首选搜索区域。只有一端时，沿相应方向搜索并留回退范围；无局部依据时，使用可靠的时间定位候选，再考虑全文。

邻段可以是已确认草稿，但需明确其尚未应用；撤销该确认时重新评估依赖它的候选。未经确认的邻段只作为弱排序信号。

前后范围指向矛盾、不同重复轮次或不兼容位置时，标记冲突，展示依据。不得强行排序后覆盖用户已经确认的对应。

### 6.3 两类余量

位置余量允许搜索越过邻段参考范围的端点，容纳半句、跨词、漏字和切分偏差。时间余量允许同一演唱内容在不同 SYN 或声部存在合理起音偏差。

文字匹配综合原文相似程度、读音相似程度、插入/删除/替换错误及相邻上下文，不要求完全相同。不能仅因为表面汉字不同就判定实际发音不同。

搜索按局部、扩展、全文逐步进行。时间和文本窗口的大小、邻段数量、候选数量及评分阈值尚未确定，需用真实工程样本校准，不在此承诺准确率或硬编码未经验证的常量。

### 6.4 多候选与重复演唱

参考文本多次出现相同句子时，优先通过前后文、已确认位置和实际时间区分。如果整段重复导致证据不足，则保留多个位置候选。

若所有候选带来的原文和读音修正相同，允许用户先确认文字，保持位置未确定；该结果不能作为唯一位置定位点。只有不同位置影响当前修改或后续定位时，才要求选择。

参考歌词只写一次、演唱却重复多次时，允许不同时间段重复引用同一范围。按不同演唱时间记录重复使用，不强制参考范围永久单调递增。

手动选择位置后，系统不自动改写它；若后续证据不一致，只提示复核。

### 6.5 无匹配时

保留识别结果，不生成看似确定的替换。提供搜索、手工选取、手工改字/读音或跳过入口。哼唱、衬词和参考歌词遗漏内容允许标记为“不使用参考校对”，不阻止其余句子完成。

## 7. 原文、读音和下游控制

### 7.1 原文与读音协同校对

替换原文后提供读音候选，并显示相对旧读音的变化；不能悄悄保留过时 Kana，也不能把自动读音视为已确认。生成读音候选失败时，保留草稿并允许手工编辑，不自动写入错误结果。

Romaji 跟随已确认的读音转换。日语特殊读法、长音、促音以及跨 Segment 发音分配允许人工修正。具体读音生成能力优先核实并复用现有链路，本文不预设新增模型或外部服务。

### 7.2 更新策略

仅原文写法变化且实际控制读音不变时，不因显示文字变化强制重跑 Kana/H。

读音变化时标记“发音控制待更新”。用户只保存文字后，必须能看到合成仍使用现有 H 数据的状态，不能显示为整体完成。

允许通过已有能力选择重新对齐 Kana、从 Segment 更新 H 或按当前 Kana 边界更新 H。若当前 Kana 文本仍旧，不能用“按当前 Kana 更新 H”冒充已经采用修正后的 Segment 读音；必须先解决两者差异。

下游覆盖范围以现有真实合同计算。某些 H 操作可能延伸至下一 Segment 起点，预览应展示实际范围，不承诺严格只到 speechEndFrameExclusive。已有手工编辑确认继续适用。

更新不修改 MIDI-P，不移动 Segment 边界，也不改写已生成 Take 的音频。新结果通过生成新 Take 验证。

### 7.3 失败与并发修改

文字保存与模型对齐分开记录状态。对齐失败后，已经保存的文字仍在，控制数据保持原状或由事务完整回滚，并保留待更新标记。

任务启动时记录 Guide、Segment 和目标控制轨版本。运行期间发生编辑时，旧候选或旧任务结果不能覆盖新内容，沿用项目已有的版本校验方式。

## 8. 紧凑交互与布局要求

### 8.1 入口和状态

工具栏增加带提示的校对图标、紧凑进度和前后待处理导航；空间不足时折入菜单，不挤掉核心时间线操作。

Segment 使用现有边框及小图标表示未检查、待确认、有歧义、已确认待应用、已应用或控制待更新等状态。状态不能仅靠颜色传达，也不永久覆盖原有歌词文字。

### 8.2 普通校对浮层

浮层展示当前文字、建议文字、读音和试听/跳过/确认操作。使用受约束宽高，长文本换行或进入扩展视图，不因内容增长推动主布局。

根据可用空间放在当前 Segment 上方或下方，避免遮挡选中段、播放头和关键操作。没有足够空间时使用临时弹窗，不压缩时间线。校对过程中选择下一段时复用浮层，不叠加多个窗口。

浮层不能抢夺正常拖动；进入文字输入后键盘操作应作用于输入框，避免误触时间线快捷键。关闭/退出模式后恢复原有编辑行为和焦点。

### 8.3 复杂校对弹窗

参考导入、全文搜索、多候选、跨段分配和批量修改预览使用弹窗。歌词全文只在这里按需展开，并自动定位到相关范围。

弹窗保留必要的 Guide 试听控制。关闭后恢复原时间线缩放、滚动和选择，不要求用户重新找当前段。未提交输入留在草稿，明确的放弃操作才丢弃。

## 9. 建议的数据分层

以下为实现建议，字段名称与具体存放位置尚未定稿，应适配现有工程持久化和事务模式。

| 数据 | 归属 | 关键内容 |
| --- | --- | --- |
| 参考歌词 | 工程 | 标识、名称、原文、版本、可选来源说明 |
| SYN 校对会话 | 源 SYN | 参考标识/版本、草稿、当前段、进度 |
| Segment 校对记录 | 源 SYN + Segment | 原值与候选值、文字/读音范围、候选位置、确认状态、源版本 |
| 时间定位 | 时间线实例 + Segment | 实例标识、参考版本/范围、确认来源、派生实际时间、重复位置关系 |
| 控制更新记录 | SYN 的受影响范围 | 已应用读音版本、目标轨版本、待更新/运行/成功/失败 |

文字修正是否确认、参考位置是否确定、是否写回源对象、下游是否更新是不同维度，不能只用一个 done 布尔值表示。

源 Segment、实例时间和参考版本是权威输入，绝对时间可缓存但必须随输入重新计算。参考范围索引需采用明确的 Unicode 索引约定并维护原文映射，避免规范化或字符计数差异导致错误高亮。

旧工程没有校对数据时按未启用处理，不迁移或重写原有歌词。草稿、定位和已应用变化都需支持保存恢复；正式应用进入现有撤销历史。

## 10. 实施范围与顺序

建议按以下顺序落地，阶段名称不代表已经完成：

1. 工程参考歌词、SYN 草稿与恢复、当前 Segment 临时浮层、手工参考范围选择、修改预览与撤销。
2. 原文/读音候选处理，以及下游待更新状态和现有局部对齐操作的衔接。
3. 参考范围模糊匹配、相邻确认点约束、实际时间定位、重复候选和跨 SYN 候选复用。
4. 用真实长歌词和重复演唱工程校准窗口及排序，完成空间受限情况下的交互验证。

完整版本需要具备上下文与时间辅助匹配；仅提供粘贴弹窗不能宣称本设计完成。自动联网找歌词、修改句子边界、改造 MIDI-P 或重新设计 Take 管理不在本次范围。

## 11. 验收场景

采用针对性的验证，不为低风险显示变化重复扩大测试。范围映射、时间定位和正式应用事务需要有明确验证。

| 场景 | 预期 |
| --- | --- |
| 长歌词，仅校对中间一段 | 自动定位附近文字，不要求从全文顶部查找 |
| 一行跨多个 Segment / 一个 Segment 跨多行 | 支持范围对应，所有 Segment 起止 frame 不变 |
| 汉字读音被边界切开 | 可分配读音，不要求改音频边界 |
| 错字、漏字、多字、假名/汉字差异 | 能提出宽松候选，低可信情况可人工处理 |
| 多次相同副歌 | 利用上下文和时间；证据不足保留多候选 |
| 候选位置不同但修正内容相同 | 可先确认文字，不强制选择位置 |
| 参考只写一次，演唱重复 | 允许重复引用，不锁死向后匹配 |
| 邻段定位点冲突 | 提示复核，不覆盖已确认关系 |
| SYN 移动、复制或无时间线实例 | 正确重算/隔离/缺省时间定位 |
| 同一源 SYN 被多实例引用 | 文字共享影响可见，实例时间分别处理 |
| 参考修改、Segment 重转录或后台任务期间编辑 | 旧关系失效可见，旧结果不覆盖新内容 |
| 已手调 Kana/H 后改读音 | 显示实际覆盖范围，更新由用户显式选择 |
| 只保存文字、对齐失败 | 保持待更新状态，不误报合成已修正 |
| 切换 SYN、关闭弹窗、重开工程 | 草稿与位置恢复，时间线视图不丢失 |
| 窄窗口、长文字、多候选 | 无新增常驻面板，无越界和关键内容遮挡 |
| 撤销批量应用 | 恢复原数据与一致状态，不改 MIDI-P 和历史 Take |

## 12. 尚待实现验证的问题

- 读音候选生成如何复用现有服务，怎样表达跨汉字的发音范围。
- 多 SYN 共享时间依据的坐标分组方式，避免不同编排互相干扰。
- 当前时间线实例是否存在额外播放变换，以及应复用的时间映射入口。
- 匹配评分、邻段数量、时间/文字余量和逐步扩大搜索的具体策略。
- 浮层尺寸、锚定位置和空间不足时的弹窗切换，需要在实际编辑器中验证。

这些细节可以在实现中调整，但不得改变本轮已确认的边界原则、实例时间定位原则、宽松匹配原则和不挤占时间线原则。
